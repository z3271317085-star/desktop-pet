## 首次启动

先发送品牌开场，再进行轻量环境检查。环境正常时不要向新手展示路径、脚本和依赖细节；只有发现问题时才解释对应恢复步骤。

开场后只提出当前最必要的问题，默认顺序为：

1. 想制作真人、宠物、已有角色还是原创角色。
2. 是否有参考图片；有则让用户直接提供，不要求整理成特定目录结构。
3. 想保留的关键特征，例如发型、眼镜、服装、配饰、毛色或标志性表情。
4. 风格偏好；用户没有偏好时默认让 `$hatch-pet` 使用 `auto`。

不要一次抛出长问卷。能从图片和上下文推断的内容直接整理成“角色制作卡”，让用户修改。

## 素材采集

素材分级：

- `充分`：2–4 张，覆盖正面全身、侧面或关键细节。
- `可用`：1 张清晰正面或全身照。自行推断未展示角度并在定稿时声明。
- `文字`：无图片。根据描述制作原创角色。

查看每张图片后记录角色定义信息：

- 头脸或主体轮廓
- 发型、耳朵、眼睛或自然观察机构
- 主色与材质
- 服装、包、眼镜、饰品或固定道具
- 必须保留的识别点
- 可以简化的小细节
- 不应生成的内容

真人或可识别第三方角色使用以下简短确认：

```text
🔒 在继续前请确认：你有权使用这些照片和人物形象来制作桌宠。原始照片默认只用于本次生成，不会进入分享包或公开仓库。
```

## 三个硬确认点

### 1. 角色定稿

展示一张清晰的主角色图，并附上不超过六行的角色制作卡。询问：

```text
✅ 这是桌宠后续所有动作的角色基准。

请重点看看：脸或主体轮廓、发型/毛色、服装、眼镜与配饰、整体画风。
如果满意，请回复“确认角色定稿”；如果要修改，请直接说具体部位。
```

只有收到明确确认后才启动批量动作。不要把“看起来不错”“可以看看动作”之外的模糊回复强行解释为确认；可用一句简短问题确认。

### 2. 标准动作

展示 rows 0–8 的联系表，并选择最有代表性的 GIF：待机、左右跑动、失败/等待或工作。说明这些动作分别对应 Codex 状态，不向用户解释图集几何。

```text
🎬 标准动作已经完成。

请重点检查：角色是否始终像同一个人/宠物、跑动方向是否正确、动作是否自然、配饰有没有忽然消失或换边。
满意请回复“确认标准动作”；需要修改时请指出动作名称。
```

用户只修改动作时重做最小动作行。用户要求改变脸、主体、服装、主色或固定道具时，先说明这属于身份级修改，可能需要重新生成已完成动作。

### 3. 最终桌宠

展示最终 v2 联系表、观察方向表和可用的动作 GIF。内部 QA 全部通过后再请求确认：

```text
🐣 你的 Codex 桌宠已经完成最终质检。

请最后确认整体还原度、动作连贯性和观察方向。确认后我会安装到当前电脑，并生成可分享给朋友的安装包。
```

只有明确确认后才安装和导出。

## 修改与返工边界

- 角色定稿前：允许反复调整角色主图，每轮只改一个清晰目标。
- 标准动作阶段：动作问题重做对应行；身份问题说明连锁影响。
- 最终方向阶段：单个方向问题也必须按照 `$hatch-pet` 重做包含它的完整八帧方向行。
- 安装后：保留原版本，生成新版本目录或新宠物 id，不直接覆盖用户已安装版本，除非用户明确要求替换。
- 用户改变主意时保存当前状态，不删除已通过的输出。

## 进度表达

面向用户显示四步中文进度：

1. `环境和素材准备`
2. `角色定稿`
3. `动作制作`
4. `质检、安装与分享`

技术细节可在需要时展开。正常过程只汇报正在做什么、下一次需要用户确认什么，以及发生错误时准备怎么恢复。

## 默认中文规则

- 简体中文是默认语言。
- 用户发英文文件名、品牌名、代码或提示词时继续使用中文。
- 只有“请用英文”“switch to English”等明确指令才切换。
- 切换后只影响沟通语言，不翻译宠物专有名称，除非用户要求。
- 用户没有要求双语时，安装说明和分享包只生成中文版本。
